# MintVault — Защищённое локальное хранилище секретных файлов для Linux Mint

**MintVault** — это автономное графическое приложение (GTK 3) и инструмент командной строки для защиты конфиденциальных файлов и каталогов на **Linux Mint** (Cinnamon, MATE, Xfce), а также совместимых дистрибутивах Debian/Ubuntu.

Приложение спроектировано в соответствии с принципами прикладной криптографии и сохранности данных:
- **100% локальная обработка:** никаких облачных сервисов, внешних серверов, подписок или телеметрии.
- **Безусловная сохранность оригиналов по умолчанию:** добавление файлов и папок в хранилище всегда создаёт зашифрованную копию внутри контейнера `.mvault`, **никогда не удаляя и не изменяя исходные файлы** автоматически.
- **Промышленная криптография:** аутентифицированное шифрование `AES-256-GCM` (OpenSSL 3.0), функция формирования ключа `Argon2id` (`libargon2`, RFC 9106) со строгой проверкой границ параметров KDF и разделение подключей `HKDF-SHA256` (RFC 5869).
- **Транзакционная защита от сбоев (Copy-on-Write):** существующее рабочее хранилище никогда не перезаписывается напрямую. Все изменения записываются во временный файл с принудительной синхронизацией на диск (`os.fsync`), криптографической самопроверкой и атомарной заменой (`os.replace`), а состояние в памяти обновляется только после успешного завершения транзакции.
- **Гибкая система настроек и двуязычный интерфейс:** поддержка тем оформления (`Системная`, `Светлая`, `Тёмная`), переключение языка (`Русский` / `English`) без перезапуска, масштабирование шрифта и автоблокировка по таймеру бездействия.

## 1. Системные требования и зависимости на Linux Mint

Приложение использует стандартные проверенные компоненты, входящие в базовую поставку **Linux Mint 21.x / 22.x** (и Debian 12 / Ubuntu 22.04+):

| Компонент | Системный пакет APT | Назначение |
| :--- | :--- | :--- |
| Python 3.10+ | `python3` | Среда выполнения приложения |
| PyCA Cryptography | `python3-cryptography` | Аутентифицированное шифрование `AES-256-GCM` и `HKDF-SHA256` (через OpenSSL 3) |
| LibArgon2 | `libargon2-1` | Памятеёмкая функция формирования ключа `Argon2id` (защита от GPU/ASIC-перебора) |
| LibSodium | `libsodium23` | Безопасное затирание ключевых буферов в оперативной памяти (`sodium_memzero`) |
| PyGObject / GTK 3 | `python3-gi`, `gir1.2-gtk-3.0` | Нативный графический интерфейс рабочего стола Linux Mint |

Установка пакетов из официального репозитория Linux Mint:
```bash
sudo apt update && sudo apt install -y python3-cryptography python3-gi gir1.2-gtk-3.0 libargon2-1 libsodium23
```

## 2. Установка, запуск, безопасное обновление и удаление

### Быстрый запуск без установки
```bash
chmod +x run_mintvault.sh
./run_mintvault.sh
```

### Проверка готовности системы (`doctor`)
```bash
./run_mintvault.sh doctor
```

### Установка и безопасное обновление в профиле пользователя (без прав root)
Скрипт `install.sh` проверяет безопасность целевого пути, копирует приложение в `~/.local/share/mintvault`, создаёт исполняемую команду `~/.local/bin/mintvault` и добавляет ярлык **«MintVault — Защищённое хранилище»** в системное меню приложений Linux Mint:
```bash
chmod +x install.sh
./install.sh
```
**Правила безопасного обновления:**
- Повторный запуск `./install.sh` поверх существующей установки обновляет только программные модули в `~/.local/share/mintvault`.
- Пользовательские контейнеры (`*.mvault`), резервные копии и файл настроек `~/.config/mintvault/settings.json` при обновлении не затрагиваются.
- Все ранее созданные контейнеры `.mvault` формата версии `1` полностью совместимы и открываются без необходимости миграции.

### Удаление программы
```bash
chmod +x uninstall.sh
./uninstall.sh
```
*Примечание:* скрипт удаления проверяет корректность пути `INSTALL_DIR` и удаляет только программные файлы приложения и ярлык меню. Ваши зашифрованные хранилища (`*.mvault`), резервные копии и настройки остаются нетронутыми.

## 3. Инструкция пользователя

### 3.1. Создание нового хранилища
1. Запустите программу и нажмите **«Создать хранилище (Ctrl+N)»**.
2. Выберите место сохранения и имя файла (например, `~/Мои_секреты.mvault`).
3. Введите надёжный мастер-пароль (дважды) и оставьте включённой опцию **«Сгенерировать аварийный 256-битный ключ восстановления»**.
4. Сохраните аварийный ключ восстановления (`XXXX-XXXX-XXXX-...`) на отдельный внешний носитель или в файл с правами `0600`.

### 3.2. Открытие, разблокировка и блокировка
- Нажмите **«Открыть хранилище (Ctrl+O)»**, выберите файл `.mvault` и введите пароль (или аварийный ключ восстановления).
- Когда вы закончили работу, нажмите **«Заблокировать (Ctrl+L)»** или закройте окно: программа принудительно затрёт мастер-ключ в оперативной памяти нулями (`sodium_memzero` / `memset`) и снимет файловую блокировку.

### 3.3. Добавление файлов и поведение при работе с оригиналами
- Нажмите **«➕ Добавить файлы»**, **«📁 Добавить папку»** или перетащите объекты мышью (Drag-and-Drop).
- **Разделение операций:** добавление файла в MintVault всегда создаёт зашифрованную копию внутри контейнера `.mvault`. Шифрование копии и удаление исходного файла — две разные операции.
- По умолчанию исходные файлы на диске никогда не удаляются.
- Если в настройках включена опция **«Предлагать удалить оригиналы после успешного добавления в хранилище»**, то **только после** полной записи контейнера на диск, `os.fsync` и криптографической проверки целостности добавленных записей (`verify_entries_integrity`) программа покажет отдельный диалог подтверждения (с кнопкой по умолчанию «Оставить оригиналы»).
- При согласии пользователя и подтверждении необратимости MintVault перед удалением каждого исходного файла проверяет через `os.lstat` и `os.O_NOFOLLOW`, что `inode`, устройство, размер и `SHA-256` файла совпадают с только что добавленным объектом, и никогда не удаляет родительские каталоги, если пользователь выбрал отдельные файлы.

### 3.4. Поиск, извлечение и удаление из хранилища
- **Поиск:** живая фильтрация по имени или виртуальному пути без учёта регистра.
- **Извлечение:** потоковая расшифровка во временный файл с проверкой тегов `AES-256-GCM` каждого блока и итогового `SHA-256`, после чего файл публикуется через `os.link` + `os.unlink` без возможности перезаписи существующих файлов. Если файловая система не поддерживает безопасную публикацию таким способом, операция завершается ошибкой, не заменяя существующий файл.
- **Удаление из хранилища:** пересобирает контейнер в режиме Copy-on-Write без удалённых зашифрованных блоков.

## 4. Система пользовательских настроек и формат конфигурации XDG

Нажмите кнопку **«⚙ Настройки»** в верхней панели главного окна для открытия диалога настроек GTK 3.

### Расположение и защита конфигурационного файла
- Путь по умолчанию: `$XDG_CONFIG_HOME/mintvault/settings.json` (обычно `~/.config/mintvault/settings.json`; в тестах может переопределяться через переменную окружения `MINTVAULT_CONFIG_DIR`).
- Каталог настроек создаётся с правами `0700`, файл `settings.json` — с правами `0600`.
- Чтение и запись защищены от символических ссылок (`os.O_NOFOLLOW`) и проверяют принадлежность текущему пользователю (`st_uid == os.getuid()`).
- Сохранение выполняется атомарно через временный файл с `os.fsync` и `os.replace`.
- **Запрет секретов:** модуль `mintvault/settings.py` никогда не сохраняет пароли, ключи восстановления или мастер-ключи и автоматически удаляет любые запрещённые поля при чтении.
- **Восстановление при повреждении:** если файл настроек повреждён, содержит некорректный JSON или недопустимые значения, повреждённый файл сохраняется в `settings.json.corrupt.<timestamp>.bak`, а приложение безопасно восстанавливает настройки по умолчанию.

### Доступные параметры в `settings.json`
| Поле | Тип | По умолчанию | Допустимые значения / описание |
| :--- | :--- | :--- | :--- |
| `theme` | `str` | `"system"` | `"system"` (системная с fallback на светлую), `"light"` (светлая), `"dark"` (тёмная). Применяется мгновенно без перезапуска. |
| `language` | `str` | `"ru"` | `"ru"` (Русский), `"en"` (English). Мгновенно переводит весь графический интерфейс без перезапуска. Сообщения CLI сохраняют совместимость со скриптами. |
| `ui_font_scale` | `int` | `100` | `85..150` (%). Масштаб шрифта интерфейса GTK 3. |
| `ask_before_deleting_originals` | `bool` | `true` | Всегда запрашивать дополнительное подтверждение перед необратимым удалением оригиналов. |
| `offer_delete_originals_after_add` | `bool` | `false` | Предлагать удалить оригиналы после успешного добавления и проверки целостности контейнера. |
| `confirm_before_vault_delete` | `bool` | `true` | Запрашивать подтверждение перед удалением объектов из хранилища. |
| `confirm_large_extraction` | `bool` | `true` | Запрашивать подтверждение перед извлечением большого числа объектов. |
| `large_extraction_threshold` | `int` | `10` | `1..10000`. Порог числа объектов для предупреждения при извлечении. |
| `close_unlocked_action` | `str` | `"lock_and_close"` | `"lock_and_close"` (автоматически блокировать и закрывать) или `"ask"` (спрашивать подтверждение перед закрытием разблокированного окна). |
| `auto_lock_minutes` | `int` | `0` | `0..480` минут (`0` — выключено). Автоматическая блокировка после бездействия (не прерывает активные фоновые операции записи). |
| `notify_long_operations` | `bool` | `true` | Показывать диалог подтверждения после успешного завершения длительных операций. |
| `default_backup_dir` | `str` | `""` | Предпочтительный абсолютный путь к каталогу для сохранения резервных копий. |

## 5. Проверка целостности и восстановление после сбоя

Для полной проверки контейнера нажмите **«🛡 Проверить целостность»** в GUI или выполните:
```bash
./run_mintvault.sh verify /путь/к/хранилищу.mvault
```
При обнаружении временных файлов `.tmp` от прерванных транзакций MintVault проверяет по PID, не принадлежит ли временный файл активному процессу, и предлагает безопасно удалить только осиротевшие файлы завершённых процессов.

## 6. Архитектура, бинарный формат `.mvault` и совместимость

Модули пакета `mintvault/`:
- `mintvault/crypto.py` — криптографические примитивы (`Argon2id`, `Scrypt`, `AES-256-GCM`, `HKDF-SHA256`, валидация границ KDF, потоковое шифрование, затирание памяти).
- `mintvault/fs_utils.py` — файловый слой безопасности (`os.lstat`, `open_safe_regular_file_for_read` с `O_NOFOLLOW | O_NONBLOCK`, `atomic_publish_extracted_file` через `os.link`, защита от Path Traversal).
- `mintvault/vault.py` — управление контейнером `.mvault` (версия формата `1`), транзакционное ядро Copy-on-Write, межпроцессная блокировка `fcntl.flock`, проверка целостности и безопасное удаление верифицированных оригиналов.
- `mintvault/settings.py` — управление пользовательскими настройками XDG.
- `mintvault/i18n.py` — словари локализации (`ru` / `en`) и форматирование величин.
- `mintvault/models.py` и `mintvault/exceptions.py` — модели данных со строгой валидацией типов и иерархия исключений.
- `mintvault/gui.py` — графический интерфейс GTK 3.
- `mintvault/cli.py` — интерфейс командной строки.

**Совместимость старых контейнеров:** бинарный формат `.mvault` (версия `1`) полностью сохранён. Контейнеры, созданные в MintVault v1.0.0, открываются по паролю и аварийному ключу восстановления, проходят полную проверку целостности и поддерживают добавление/извлечение файлов.

## 7. Обнаруженные и исправленные уязвимости

В ходе аудита безопасности были выявлены и устранены следующие уязвимости и ошибки надёжности:
1. **[КРИТИЧЕСКИЙ / ВЫСОКИЙ] Отказ в обслуживании (CPU / OOM DoS) и переполнение `uint32` через параметры KDF в заголовке (`mintvault/crypto.py`, `mintvault/models.py`, `mintvault/vault.py`):**
   - *Проблема:* параметры `time_cost`, `memory_cost_kib`, `parallelism` и список `key_slots` читались из открытого JSON-заголовка до проверки `header_mac_hex` и передавались в `libargon2` / `Scrypt` без проверки границ.
   - *Исправление:* добавлена функция `validate_kdf_params` (проверяется в `inspect_header`, `unwrap_key_slot` и `derive_kek`), ограничивающая `time_cost` (`1..64`), `memory_cost_kib` (`8192..1048576` КиБ), `parallelism` (`1..16`), длину соли (`16..64` байт) и число слотов (`1..4`).
2. **[ВЫСОКИЙ] Неограниченное выделение памяти при чтении длины блока в `decrypt_file_stream` (`mintvault/crypto.py`):**
   - *Проблема:* 32-битная длина чанка `plain_len` распаковывалась из 5-байтового заголовка чанка до проверки GCM-тега и передавалась в `src_stream.read()`, позволяя инициировать выделение до 4 ГБ ОЗУ одним чанком, а также допускались пустые чанки в непустых файлах.
   - *Исправление:* введён жёсткий лимит `MAX_CHUNK_SIZE = 4 МиБ`, контроль непревышения `expected_plain_size` и запрет пустых чанков для непустых файлов.
3. **[ВЫСОКИЙ] Неполная проверка полей заголовка, индекса и непрерывности секции данных (`mintvault/vault.py`):**
   - *Проблема:* не проверялись `header["format_version"]`, `header["cipher"]`, совпадение `vault_uuid` в индексе и заголовке, уникальность `entry_id` и `virtual_path`, а также отсутствие неаутентифицированных зазоров (slack space) или пересечений между блобами файлов. Кроме того, `verify_integrity()` не проверял пути записей на Path Traversal.
   - *Исправление:* внедрена единая функция `_validate_and_parse_index`, проверяющая все инварианты индекса и строгое разбиение секции данных `[data_start, index_offset)` как при `unlock()`, так и при `verify_integrity()`.
4. **[ВЫСОКИЙ] TOCTOU-гонки при открытии исходных файлов и публикации извлекаемых файлов (`mintvault/fs_utils.py`, `mintvault/vault.py`):**
   - *Проблема:* исходные файлы открывались через `open(src_path, "rb")` после `os.lstat` без `O_NOFOLLOW`, а при извлечении `os.replace(tmp_extract_path, out_path)` мог перезаписать целевой файл, появившийся в окне гонки.
   - *Исправление:* реализованы `open_safe_regular_file_for_read` (`O_RDONLY | O_NOFOLLOW | O_NONBLOCK` + сверка `os.fstat(fd)`), пошаговое создание проверенных каталогов `ensure_safe_directory_tree` и атомарная публикация без перезаписи `atomic_publish_extracted_file` через `os.link` + `os.unlink`.
5. **[ВЫСОКИЙ] Повреждение состояния в памяти при прерывании транзакции записи (`mintvault/vault.py`):**
   - *Проблема:* `_write_atomic_transaction` модифицировал `self._header` и `entry.blob_offset` существующих записей в памяти до завершения записи на диск, из-за чего при ошибке записи последующее чтение из открытого объекта обращалось по неверным смещениям.
   - *Исправление:* транзакция работает с изолированными копиями заголовка и записей и обновляет состояние объекта только после успешного выполнения `os.replace`.
6. **[СРЕДНИЙ] Защита временных файлов активных процессов и блокировок (`mintvault/vault.py`, `mintvault/fs_utils.py`, `install.sh`, `uninstall.sh`):**
   - *Исправление:* `find_orphaned_temp_files` и `cleanup_orphaned_temp_files` проверяют файлы через `os.lstat` и не удаляют временные файлы живых процессов (`os.kill(pid, 0)`); `create_backup` захватывает файловую блокировку; в `normalize_virtual_path` заблокированы обратные слеши `\`, управляющие символы и имена длиннее 255 байт; в `install.sh`/`uninstall.sh` добавлены проверки `INSTALL_DIR` и экранирование пути в `mintvault.desktop`.

## 8. Модель угроз и оставшиеся ограничения

- **Скомпрометированная среда выполнения (кейлоггеры, вредоносное ПО от имени пользователя или `root`):** приложение не может защитить данные, если злоумышленник уже имеет доступ к процессу пользователя или ядру ОС в момент ввода пароля или работы с разблокированным хранилищем.
- **Ограничения управления памятью в интерпретаторе Python (CPython):** мастер-ключ, подключи и C-буферы в `mintvault/crypto.py` хранятся в изменяемых буферах (`bytearray` / `ctypes`) и принудительно затираются через `sodium_memzero` / `memset`. Однако неизменяемые объекты `str`, создаваемые внутри виджетов GTK (`Gtk.Entry.get_text()`) или стандартного ввода Python в момент ввода пароля, управляются сборщиком мусора CPython и не могут быть гарантированно перезаписаны на месте без модификации самого интерпретатора.
- **Автоблокировка и открытые модальные диалоги GTK:** таймер автоблокировки по бездействию безопасно блокирует хранилище и затирает ключи в памяти, не прерывая активные фоновые дисковые операции (`is_busy`).
